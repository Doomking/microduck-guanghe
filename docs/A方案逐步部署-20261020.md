# A 方案 · 一步一步的部署清单（我这台）· 2026-10-20

> **A 方案是什么**：装 kissqy 整套（R17 V167 / control.43），再把它缺的那一样——**「IMU 模块直连主板 I²C」**——用我们 fork 的 robotd / padd 补上。

> **口径**：跟 [我的记录](../我的记录.md) 一致，只写我这台。第一台的历程当**证据**用（[10-12 整套上机](HD1910-20261012-kissqy整套上机.md)、[10-15 陀螺融合上机](HD1910-20261015-IMU乱跳根因与陀螺融合上机.md)）。
> **总方案在哪**：[训练与部署方案](训练与部署方案-20261020.md)（本文只展开它的「阶段 0 · 铺跑道」）。
> **外部依据**（fork 分支 `hd1910-v167-gyro-fusion`）：[IMU-MODULE.md](https://github.com/fanhao375/Microduck-kissqy/blob/hd1910-v167-gyro-fusion/IMU-MODULE.md) · [独立固件安装](https://github.com/kissqy/Microduck-kissqy/blob/main/release-assets/README.md) · [中控使用说明](https://github.com/kissqy/Microduck-kissqy/blob/main/microduck-hd1910/firmware/console/README.zh-CN.md)

## 步 0 · 先确认这几件事

后面的命令我按下面的「默认那台」写死了。实物跟它不一样，就按右下角那列改。

| 要确认的 | 怎么查 | 默认（本文按它写） | 不一样就改 |
|---|---|---|---|
| 主板版本 | 背面丝印 | **V1.12 + AIC8800** | 不是 V1.12 就不需要步 2 的换引导，直接刷原版镜像 |
| HAT 是哪版 | 板载 IMU 是 BMI088（C1）还是 LSM6DSV16X（D1） | **C1**（我们打的那版） | D1 的 LSM6DSV16X 模块**必须用 0x6B** |
| IMU 模块 | 手上模块的丝印 | **BNO085** | LSM6DSV16X 转接板 → `install` 参数换 `lsm6dsv16x`、地址写 0x6A/0x6B |
| 接哪条 I²C | 打算怎么接（见步 7） | **40 针 27/28 脚 → `/dev/i2c-4`，0x4B** | HAT J5 → `/dev/i2c-3`；J6 改电阻 → `/dev/i2c-4` |
| 装了 ToF 吗 | 实物 | **没装** | 装了就去掉 `--no-tof` |
| 装了摄像头吗 | 实物 | **装了**（09-28 已出图） | 没装就加 `--no-camera` |

再准备的东西：**16 GB 以上的 TF 卡**（一条 50 Hz 录像约 3 MB/分钟）+ 读卡器；**一台 Linux 或 WSL2**（步 2、步 8 用，Mac 做不了：要 loop 挂载和 `dpkg-deb`）；**10 A 级电源**（整机走路会掉电，这不是软件问题）；电脑上有 Python 3.10+（开中控用）。

## 步 2 · 做一张 V1.12 能开机的卡（Linux / WSL2） · ⚠️ 未上机烧卡

原版 R1 用的是 Armbian 自带的主线 U-Boot，**咱们这块 V1.12 板起不来**（局域网里找不到）。我们的脚本只换引导和开机配置，他的固件、模型、首次配网、账号全部原样保留。

```bash
# 把镜像和脚本放到 Linux 上，脚本就在仓库里
cd <放镜像的目录>
sudo bash /path/to/microduck-replica/tools/radxa/kissqy-r1-v112.sh \
    microduck-zero3w-0.15.1-R1.img.xz \
    --no-tof \
    --overlay i2c4-m0
```

- `--no-tof`：没装 ToF，关掉它的服务（不关的话它不停崩溃重启，能占满一个核）。
- `--overlay i2c4-m0`：**给 IMU 模块开路**（40 针 27/28 → `/dev/i2c-4`）。要接 HAT J5 就走 `/dev/i2c-3`，镜像自带 `i2c3-pihat`，**这一项不用加**。接 J6 改电阻那条也是 I²C4，照旧加。
- 摄像头保留，**不加** `--no-camera`。
- 脚本会自己下瑞莎的 u-boot 包（`u-boot-rk2410_2017.09-64-39cd993`，sha256 `fb319203…b1ce7`），校验不过就停。

**过了长这样**：最后打印 `做好了：microduck-zero3w-0.15.1-R1-V112.img` 和它自己的 sha256。
**对不上/中途停**：看它是「校验值不对」（镜像下坏了）还是「找不到 overlay 文件」（镜像版本换了，先核对再改脚本）；脚本中途失败不会留下半成品，重跑即可。
**这一条的风险**：脚本是**离线验证过、还没真的烧过卡**。第一台那张卡**别动**，我们用的是新卡。

## 步 3 · 烧卡 + 首次配网 + SSH（Mac + 板） · ⚠️

1. **烧卡**：用 [Armbian Imager](https://imager.armbian.com/)（选「自定义镜像」）或 balenaEtcher，烧 **`...-R1-V112.img`**（已经解压好的那个）。
2. **插卡上电**，等 1～3 分钟。
3. **配网**：手机/电脑连热点 **`Microduck-kissqy`**，密码 **`12345678`**，打开 **http://10.42.0.1:8088**，按页面设置家里 Wi-Fi 和**新的系统登录密码**。
4. **找 IP、SSH**：路由器管理页看 `radxa` 那台，或 `ssh radxa@<IP>`。用户名就是 **`radxa`**。

**过了长这样**：能 SSH 进去，`uname -a` 出来是 arm64；`ls /dev/i2c-4` 能看到设备（走 27/28 那条的话）。
**连不上**：先确认绿灯是不是在 heartbeat 双闪（正常）；没网就用 OTG 口插电脑当串口救（我们的镜像说明里有，见 [镜像使用说明](../tools/radxa/镜像使用说明.md) 第 3 节）。
**⚠️**：镜像里带的是**别人那台**的装配标定（包括 IMU 那份被打成「已确认」的方向），**刷完必须先换成自己的**（步 6），在那之前**别开运动**。

## 步 4 · 降温 + 记一条温度基线（板） · ✅

第一台就是在这里栽的：主板 85–92 ℃、CPU 被锁在最低档 408 MHz，网页摇杆根本来不及响应。

```bash
scp /path/to/microduck-replica/tools/radxa/duck-quiet.sh radxa@<IP>:~/
ssh radxa@<IP>
sudo bash ~/duck-quiet.sh status          # 现在的温度、频率、最吃 CPU 的进程、相关服务
sudo bash ~/duck-quiet.sh measure 300 刷完基线   # 每 5 秒记一次，300 秒，存 CSV
sudo bash ~/duck-quiet.sh quiet           # 关掉走路用不到的开机自启服务，记下原状态
```

**过了长这样**：`status` 里温度掉下来、频率从 408 MHz 回到正常档；`quiet` 之后 `mediad` / `tofd` 这类变成停用。
**要回滚**：`sudo bash ~/duck-quiet.sh restore`。
注意它**不动蓝牙**（以后接蓝牙手柄要用）。

## 步 5 · 升级到 R17 V167 / control.43（板，SSH 一条命令） · ✅

镜像里预装的是 **control.40**；kissqy 的整套（R17 V167）在 **control.43** 上，我们 fork 的修改也是基于 control.43。这一条走官方的**独立固件 SSH 安装**，全程在板上跑，不需要 Windows 中控：

```bash
(
  set -e
  microduck_fw_dir=$(mktemp -d "$HOME/microduck-control43.XXXXXX")
  curl -fL --progress-bar \
    -o "$microduck_fw_dir/Microduck-Robotd-FT6-R17.tar.gz" \
    "https://github.com/kissqy/Microduck-kissqy/raw/refs/heads/main/microduck-hd1910/firmware/console/updates/Microduck-Robotd-FT6-R17.tar.gz"
  printf '%s  %s\n' \
    'bcfd5c183c697b9c4e0fdbd563d995eda6a48331a7c49b9e76d20bd156c65cce' \
    "$microduck_fw_dir/Microduck-Robotd-FT6-R17.tar.gz" | sha256sum -c -
  tar -xzf "$microduck_fw_dir/Microduck-Robotd-FT6-R17.tar.gz" -C "$microduck_fw_dir"
  sudo bash "$microduck_fw_dir/Microduck-Robotd-FT6-R17/service.sh" upgrade
)
```

**过了长这样**：装完等机器人服务 **1/4～4/4** 就绪；`robotd` 这时报「舵机总线上没有机器人」——**这是正常的**，原版 robotd 只认挂在舵机总线上的 IMU 小板，还没轮到你装模块那一步。校验值不对会自己停。
**下不动**：给 root 的 curl 临时加代理（第一台就是这么过的，见 [10-12 整套上机](HD1910-20261012-kissqy整套上机.md) §3.2）。
**⚠️ 这一步之后，「中控里的安装/升级固件」就是禁区**（理由见文末速查）。

## 步 6 · 换成这台的标定（Mac 中控 + 板） · ✅

**目的**：把 kissqy 镜像里那份**样机**标定换成**这台**的。**在那之前不要 HOME，也不要开运动。**

1. 解压中控 ZIP，在里面执行 **`bash start.command`**（macOS 就是这条），浏览器会打开 `http://127.0.0.1:8090`。
2. 页面顶部填 SSH 地址 **`radxa@<IP>`** 和密码，点连接，等 **1/4～4/4** 走完。
3. 进**关节工作台**，逐关节核对**零位、方向、限位**——拿 Mac 调试台的记录对：**15 颗方向全是 −1**（HD-1910 读数增大方向跟官方 XL330 相反），舵机自己的零位已经在 10-10 写进 EEPROM 了，**不需要重校零点**。
4. **IMU 那一节先别动**（模块还没装，步 11 再回来）。
5. 实时反馈里 IMU 身体姿态那几行，先只当「有数就行」。

**过了长这样**：方向列 15 颗全是 −1、限位跟官方折叠基准对得上。
**⚠️**：这一步不点「切到运动模式」——`commissioning`（标定模式）不加载运动策略，正好是我们现在要的。

## 步 7 · 装 IMU 模块（真机，断电） · ⚠️ 只有 27/28 飞线那条在第一台用过

**硬要求**：**3.3 V** 供电；**装在躯干上，不是头上**（策略要的是躯干的姿态，HAT 在头里会跟着脖子转）；**用螺丝固定**，别胶粘（第一台胶粘装歪 8.5°，模型一接管就冲）；线过关节/过脖子留余量，两头做应力释放。

| 接法 | 接到哪 | 板上设备 | 要做什么 | 测过没 |
|---|---|---|---|---|
| **默认** | 40 针 **27/28 脚**（+ 就近取 3.3 V / GND） | `/dev/i2c-4` | 做卡时加了 `--overlay i2c4-m0`（步 2 已做） | **✅ 真机**（BNO085 0x4B） |
| 省事 | HAT **J5**（40 针 3/5 脚，JST-SH 4 针，Qwiic 线直插） | `/dev/i2c-3` | 镜像默认已开 `i2c3-pihat`，**不用改任何配置** | ⚠️ 没测过 |
| 免飞线 | HAT **J6** 改电阻（拆 R18/R19、贴 R16/R17）→ 变成 27/28 | `/dev/i2c-4` | 跟默认那条一样 | ⚠️ 没测过 |

**地址别撞**（接 J5 之前一定要看）：C1 版 HAT 上有音频 aic3104（0x18）、BMI088（0x19/0x68）；D1 版有板载 LSM6DSV16X（0x6A）。**BNO085（0x4A/0x4B）两版都不撞**；D1 上的 LSM6DSV16X 模块**必须用 0x6B**（SA0 接高）。细节见 [镜像 R1 分析](HD1910-20261012-kissqy镜像R1分析.md) §9。

**装完检查**：

```bash
ls /dev/i2c-4            # 走 27/28 或 J6 改线的话，要有这个设备
sudo i2cdetect -y 4      # BNO085 应在 0x4B（或 0x4A）；接 J5 就把 4 换成 3
```

**看不到 `/dev/i2c-4`**：`i2c4-m0` 没开或没生效。换了瑞莎引导以后**改 `armbianEnv.txt` 不生效**，要改 `/boot/extlinux/extlinux.conf` 的 `fdtoverlays`。

## 步 8 · 编译我们 fork 的三个程序（Linux / WSL2） · ✅

**注意**：编的是**我们带 IMU 支持的那一版**（不是 kissqy 原版）。分支 `hd1910-v167-gyro-fusion` 和 `hd1910-v167-trunk-imu-i2c` 指同一个提交。

```bash
git clone https://github.com/fanhao375/Microduck-kissqy.git   # 也可以先 fork 到自己名下再 clone
cd Microduck-kissqy
git checkout hd1910-v167-gyro-fusion

cd microduck-hd1910/firmware
python3 prepare-V167.py                      # 恢复 kissqy 从 git 里去掉的随包资源
export DUCK_SYSROOT=~/.cache/duck-sysroot
export DUCK_DEBIAN_MIRROR=https://mirrors.ustc.edu.cn/debian   # 国内下 Debian 包慢，可省
sh scripts/cross-sysroot.sh                  # 解 arm64 包，最后打印几行 export，照着执行
cargo board --locked -p robotd -p robotctl -p padd
```

**两只脚要绕开的坑**：
- **别跑 `build-V167.sh`**：它要求源码跟 kissqy 的发布逐字节一致，我们改过，一定失败；
- **别拿错文件**：`packaging/robotd`、`packaging/padd` 是 `prepare-V167.py` 还原出来的**kissqy 原版**。要用的是 **`target/aarch64-unknown-linux-gnu/release/`** 下面的 `robotd`、`robotctl`、`padd`。

需要 Rust 1.99+、`aarch64-unknown-linux-gnu` 目标、cargo-zigbuild 和 zig。
**过了长这样**：三个文件编出来，`file` 一看是 ARM aarch64。

## 步 10 · 装 IMU 支持（板，SSH） · ✅ 真板一次通过（回撤 ⚠️）

**前置**：**舵机电源开着**、**扶住或吊起鸭子**（脚本会卸力）。

```bash
sudo bash ~/replica/imu-module-install.sh install ~/replica bno08x /dev/i2c-4 0x4B
# 接口不同就改后三个参数：lsm6dsv16x / /dev/i2c-3 或 /dev/i2c-4 / 0x6B
```

脚本按顺序做：**查**（是不是 control.43、三个程序是不是完整 arm64、`service.sh` 对不对、`/dev/i2c-N` 在不在）→ **停 padd、卸力、停 robotd** → **备份**到 `/opt/robot/imu-module-backup-<时间>/` → **换文件**（9 个程序/脚本 + 3 份清单 + 两份 `robotd.toml` + 标定 + 启动配置）→ 写 `[trunk_imu]` → 重做 robotd 的启动配置（允许 `/dev/i2c-*`）→ **启动并核对**（四步启动、`busStatus`、padd）。全程写 `/var/log/imu-module-install.log`。

**过了长这样**：最后报告 IMU 来源是模块、IMU 方向**还没确认**、没有参数文件；`busStatus` 里出现 `imu_source` 和 `native.hd1910.servo_parameters` 两个字段（**只有这一版有**，这就是「装上了」的判据）。
**失败**：备份之后任何一步失败它**自己回撤**；手动回撤 `sudo bash ~/replica/imu-module-install.sh rollback <它打印的备份目录>`（**用这次新打的备份**，别用旧的）。
**把备份目录记下来**。
**⚠️**：`rollback` 还**没在真板上跑过**。

## 步 11 · 确认 IMU 的安装方向（板 + 鸭子） · ✅ 第一台跑过

**没确认过，robotd 在运动模式下拒绝上力。** 两种办法，选一个：

**A · robotd 自带（推荐，走 SSH）**：

```bash
S=/opt/robot/feetech-ft5-r5/service.sh
sudo bash $S disable                            # 切调试模式，会卸力
sudo bash $S bus verify-imu --confirmed
sudo bash $S enable                             # 回运动模式
```

第二条命令运行时：先让鸭子**直立**（离竖直不超过 5°，卸了力手扶很难做到，用垫块/支架撑住），再在 **20 秒内**把整只鸭子**往前低头 15°～30°**并保持，等命令返回。
**别在 kissqy 中控里点「保存安装确认」**：它只等 15 秒，模块这一步最多要 20 秒，会超时、什么都不存。

**B · 站 HOME 校零点**（模块装得不太正时用，第一台用的是这个）：
先确认装法跟 `bno08x` 默认安装方向对得上 → 在 `hd1910-calibration.toml` 的 `[imu_mounts.bno08x]` 里写 `verified = true`（四元数要归一化）→ 用 `tools/radxa/onboard-analysis/` 的 `imu_tilt_check.py` 查四个方向都对 → 站 HOME，`capture_home.py` 取数 → 电脑上 `sim_home_tilt.py` 算出应有倾斜 → `imu_mount_fix.py` 算新四元数 → 写回 → 复测到 1° 以内。
**注意**：这几个脚本里写死了用户名 `duck` 和 `/home/duck/...`，**kissqy 镜像是 `radxa`**，用之前先改路径。

**过了长这样**：`check` 里 IMU 方向变成**已确认**；`service.sh` 切回运动模式后能上力。

## 步 12 · 切陀螺融合（板，SSH，先卸力） · ✅ 10-15 真机

**为什么**：BNO085 自己融合出来的姿态，走路时隔一阵就在 20 ms 里跳 20–60°，模型以为在倒——这就是「走两三步就摔」的根因。切 `gyro` 以后用芯片的陀螺积分接住：第一台从「推杆 9 s 摔 2 次」变成「推杆 60 s 一次没摔」。**默认是 `chip`，要自己切。**

**两份 toml 都要改**（`robotd.saved.toml` 是升级/重建配置时的来源）。**必须用下面这条命令**（板上 kissqy 自己的 `configure.py`），**不能用 nano/sed 手加**：同一节同一个键写两行，TOML 就坏了，**哪个版本的 robotd 都会在启动第 1 步退出**。先 `sudo -v` 输一次密码，免得 sudo 把粘进去的行当密码读走：

```bash
C=/etc/robot/feetech-ft5; S=/opt/robot/feetech-ft5-r5/service.sh
sudo grep -n 'trunk_imu\|i2c_address\|bno08x' $C/robotd.toml $C/robotd.saved.toml   # 先看：i2c_address 每份只有一行
sudo python3 - gyro <<'PY'
import sys, tomllib; from pathlib import Path
sys.path.insert(0, '/opt/robot/feetech-ft5-r5'); from configure import dumps, atomic_write
mode, log = sys.argv[1], (sys.argv[2] if len(sys.argv) > 2 else None)
assert mode in ('chip', 'gyro') and (log is None or log == 'off' or log.startswith('/')), sys.argv
for p in (Path('/etc/robot/feetech-ft5/robotd.toml'), Path('/etc/robot/feetech-ft5/robotd.saved.toml')):
    d = tomllib.loads(p.read_text()); t = d['trunk_imu']; assert t.get('source') == 'bno08x', p
    t['bno08x_fusion'] = mode
    if log: t['bno08x_raw_log'] = log
    atomic_write(p, dumps(d)); print(p.name, tomllib.loads(p.read_text())['trunk_imu'])
PY
sudo bash $S reconnect      # 先卸力，再重启 robotd、拉起 padd —— 扶住鸭子
```

**看融合计数**（robotd 在运动模式下才有）：

```bash
sudo bash $S report 2>/dev/null | python3 -c 'import json,sys;r=((json.load(sys.stdin) or {}).get("native") or {}).get("imu_reader");f=(r or {}).get("fusion") or {};print("没有 imu_reader（robotd 不在运动模式？）" if r is None else (f.get("mode"),"disabled=",f.get("disabled"),f.get("counts"),"raw_log=",r.get("raw_log")))'
```

**上机顺序**（出问题就退回上一步）：
1. **影子（默认 `chip`）**：什么都不用改。要看原始数据就先把上次的日志挪走（64 MB 封顶是跨重启累计的），再把第二个参数换成日志路径。录静站 60 s、各方向倾斜、推几次杆。
2. **`gyro` 静站**：`reconnect` 后静站 5 分钟——`theta_deg` 每个 10 s 窗口中位应 < 0.5°、P90 < 1°，`realign_long`、`realign_gap`、`fallback` 不涨。
3. **`gyro` 走路**：同参数、同地面，`chip` / `gyro` 轮着来（前后对称，电池掉电对两边公平）。主指标是**推杆时每分钟摔几次**。
4. **故意摔、抱起来放平**：静止后 2 秒内积分姿态应回到跟芯片差 1° 以内。

**什么时候立刻退回 `chip`**：直立走路时发布的姿态出现 >5° 台阶且前后 ±2 帧里有 `realign_long` / `realign_gap` / `fallback` / `follow`（1 次就退）；静站任一 10 s 窗口中位 > 0.5° 或 P90 > 1°；计数里 `disabled`。判据脚本 `judge_block.py`（**电脑上跑**，只用标准库）。规则来龙去脉见 [10-15 记录](HD1910-20261015-IMU乱跳根因与陀螺融合上机.md) §5.5。

## 步 13 · 舵机参数与滤波（板，SSH，可选） · ⚠️

**先跑对照**，确认整条路径正常：

```bash
S=/opt/robot/feetech-ft5-r5/service.sh
sudo bash $S servo-parameters 5 0 1000    # 跟「不设参数文件」的寄存器状态逐字节相同（有测试）
```

**再试目标值**（每条命令都会**卸力并重启 robotd**，**扶住或吊起鸭子**）：

```bash
sudo bash $S servo-parameters 3 0 700     # P D 转矩限制，15 颗（含嘴巴）用同一组
sudo bash $S servo-parameters-clear       # 删掉参数文件 = 回到 V167 原版
```

- 范围：**P 1～32、D 0～64、转矩限制 200～1000**，整数；文件在 `/etc/robot/feetech-ft5/servo-test-parameters.json`；
- **下次 HOME 上力时生效**，写进舵机 RAM，**不写 EEPROM**；卸力后 P 恢复、D = 0、转矩 1000（跟原版一样）；
- **为什么先 D=0**：训练模型里没有 D，真机带 D 会颤（D=20～40 时高频颤 51%，D=0 降到 4–8%）；
- **恢复**：`servo-parameters-clear`；文件写坏了 robotd 会停在「等总线」，也是这条恢复。

**头、腿滤波**（联合 Walk 模型）：

```bash
sudo bash $S models                             # 看当前 Walk 的模型标识
sudo bash $S joint-filters <模型标识> 0.50 0.70   # 头部 腿部，0.10～1.00
```

**⚠️ 验证状态**：「**不设**参数文件」那条路真机跑过；「**设了**参数文件」那条**还没上真机**——所以先跑 `5 0 1000` 对照，再上新值，而且新值**先吊着试**。

## 步 14 · 上机阶梯验收 + 采基线数据（真机 + Mac） · ✅

**安全前置（每次上机都走）**：**10 A 级电源**（整机走路掉电是老毛病，不是软件问题）；软起步；低压线 ≥ 6.6 V；转矩上限；D=0 或 5～10；网页/常驻服务停掉（步 4）。

**阶梯（不许跳）**：
1. **趴着只读**：不开力，看 15 颗关节角、IMU、电压都在动。
2. **卸力状态**：确认能干净卸力、重新上力。
3. **托着测姿势**：吊着/托着让它跑姿势，看方向、限位。
4. **放地上短时**：先几秒，再十几秒。
5. **连续走 ≥ 20 s**：推满摇杆，**一次不摔**。

**采数据**（第一台用的就是这套，脚本在 `tools/radxa/onboard-analysis/`）：

```bash
scp -r /path/to/microduck-replica/tools/radxa/onboard-analysis radxa@<IP>:~/
# 里面 duck-rec.service / duck-journal.service 写死了 duck 和 /home/duck，先改成 radxa 再装
python3 duck_rec.py 60 run-<标签>.jsonl         # 50 Hz 记关节/IMU/安全/摇杆，约 3 MB/分钟
python3 duck_health_log.py <输出.csv>            # 每 0.5 秒记电压、最热舵机、CPU 温度频率、WiFi/蓝牙
```

录像文件名带**开机编号前 6 位**（主板没有 RTC，每次开机时钟会回拨，**按开机编号找文件**：`cut -c1-6 /proc/sys/kernel/random/boot_id`）。

分析在**电脑上**跑：`walk_report.py`（推了几次杆、有没有交替迈步、倒没倒）、`failure_onset.py`（失控转折点）、`imu_consistency.py`（IMU 自洽）、`judge_block.py` / `ab_blocks.py`（融合判据与 A/B）。

**M0 验收（跑道铺好）**：推满摇杆**连续走 ≥ 20 s 不摔**；整机**不重启**；控制环稳在 **20 ms**（不掉到 25 ms）；有一轮能回放的 50 Hz 录像 + 电压温度曲线。

## 装完之后 · 禁止动作速查

| 别做 | 为什么 | 做了怎么办 |
|---|---|---|
| **点 kissqy 中控的「安装 / 升级固件」** | 会装回他的 robotd（不认 IMU 模块→读不到 IMU、上不了力）和他的 padd，还**删掉参数文件** | 重跑一遍步 10 |
| `systemctl restart robotd` | **robotd 停/重启/崩溃都不卸力**，鸭子会带着扭矩失控 | 调参一律走 `service.sh` 子命令 |
| 掉电/换电池/舵机重启后直接 HOME | robotd 以为还上着力，会直接返回，舵机带着上电默认 P32/D40 上力 | **先卸力，再 HOME** |
| 用 nano/sed 改 `robotd.toml` | 同一个键写两行 = 所有版本 robotd 启动第 1 步退出 | 用步 12 那条 `configure.py` 命令 |
| 切回原版前不卸电 | P 可能停在文件里的旧值 | 给舵机**断一次电**回到出厂值 |
