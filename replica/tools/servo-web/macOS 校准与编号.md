# macOS：给 HD-1910 编号与校准

飞特的 FD 调试软件**只有 Windows 版**（[`../飞特/`](../飞特/README.md)）。Mac 上不用装虚拟机、不用装 Windows：用同目录的网页调试台（Python + 浏览器），编号、开保护、校准都在里面做。

| 要在 Mac 上做 | 用什么 |
|---|---|
| 改 ID（编号） | 调试台「单颗操作」→ 改 ID → 写 ID |
| 开过流 / 过压保护 | 同上，「写寄存器」，或直接改 ID 时一起 |
| 中位 / 零点校准 | 调试台「一键校准」（0x0B 位置校准指令） |
| 拉滑杆看舵机转 | 调试台主页面的滑块 |
| 体检（只读） | `servo_report.py` |

**不需要**：FD、`CH340_URT.rar`（那是 Windows 的包）。

接线、飞线、供电、上电顺序、改哪些 EEPROM 参数、ID 对照表、校准基准怎么摆 —— **全跟 Windows 那份一样**，见[调试记录 · 舵机配置](../../调试记录.md#舵机配置--拿到货一步一步做)。这份只写 Mac 上不一样的地方，不重复。

⚠️ **上电顺序跟平台无关，先插 USB、再给舵机上电。** 反了总线会被压在 2.1 V，一颗都不应答（[踩坑记录 · 工具](../../踩坑记录.md#工具)）。

---

## 1. 看 Mac 认没认到串口

URT-2 是 **CH343**（WCH，USB VID `0x1a86`）。Windows 10/11 自带驱动，**macOS 不保证**。

插上 URT-2，然后：

```bash
ls /dev/cu.*
```

| 看到什么 | 意思 | 下一步 |
|---|---|---|
| `cu.usbmodem*` | 系统自带 CDC 驱动认到了 | 直接去第 2 节 |
| `cu.wchusbserial*` | WCH 驱动已装好 | 直接去第 2 节 |
| 只有 `cu.Bluetooth-Incoming-Port`、`cu.debug-console` | **没认到**，要装驱动 | 装驱动，见下 |

**装 WCH 驱动**：从 [WCH 官方仓库 `WCHSoftGroup/ch34xser_macos`](https://github.com/WCHSoftGroup/ch34xser_macos) 或 [wch.cn 下载页](https://www.wch.cn/downloads/CH341SER_MAC_ZIP.html) 拿 CH34x VCP 驱动（支持 CH340/CH341/**CH343**/CH9102 等）。

- macOS 11 及以上：**下载 dmg 版**，拖 `CH34xVCPDriver` 进「应用程序」，再从启动台打开这个 App，点 **Install**
- 装完在「系统设置 → 隐私与安全性」里允许这个扩展（macOS 13+ 可能要求重启后才生效）
- 装好再 `ls /dev/cu.*`，应该出现 `cu.wchusbserial*`

装完还是看不到，查：`system_profiler SPUSBDataType | grep -A4 -i "1a86\|CH34"` —— 能看到 `1a86` 说明 USB 层认到了，是驱动没生效；连 `1a86` 都没有就是线或者口的问题。

## 2. 起调试台

```bash
cd tools/servo-web
python3 -m venv .venv                              # 只建一次
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python server.py --port /dev/cu.wchusbserial110   # 串口号换成第 1 节看到的
```

浏览器开 **http://127.0.0.1:8080**。

`--port` 给不给都行：不给、或者串口打不开，页面照样起（假总线），顶栏出个串口下拉，插好 USB 选一个点「连接」就接管，不用重启。

常用参数：

| 参数 | 默认 | 什么时候用 |
|---|---|---|
| `--port` | — | 串口号，如 `/dev/cu.usbmodem1101`、`/dev/cu.wchusbserial110` |
| `--ids` | `20-24,30-34,10-14` | 启动时扫哪些 ID、页面按哪些 ID 建滑块。单颗编号不用改它，页面里点「全网扫描」就行 |
| `--fake` | — | 不接舵机，纯模拟，先熟悉界面 |
| `--http-port` | 8080 | 8080 被占时换一个 |

⚠️ **串口同一时间只能一个程序占。** 调试台、`servo_report.py`、FD 不能同时开。

## 3. 编号（单颗改 ID）

飞特出厂 **ID 全是 1**，15 颗全一样，所以必须**一颗一颗**来。

```
1  总线上只接这一颗（飞好线那根），先插 USB 再上电
2  起调试台（第 2 节），浏览器打开
3  页面 →「单颗操作」→ 点「全网扫描 0–253」→ 几秒后「改 ID」左边那个下拉里出现 `1 · 非标准 ID`
4  「改 ID」：左边选 1 → 右边选目标 ID（下拉就是 15 个标准位，已占用的标了「已占用」，默认选第一个空位）
5  点「写 ID」。确认框会提示「总线上最好只接这一颗」—— 对，就是只接了一颗，确定
6  日志里出「改 ID 1 → 22：新 ID ping 得通」成了；出「ping 不通」就是没写进去
```

**目标 ID 按表**（同[调试记录 · 舵机配置](../../调试记录.md#舵机配置--拿到货一步一步做)）：

| ID | 关节 | ID | 关节 | ID | 关节 |
|---|---|---|---|---|---|
| **10** | 右髋 yaw | **20** | 左髋 yaw | **30** | 颈 pitch |
| **11** | 右髋 roll | **21** | 左髋 roll | **31** | 头 pitch |
| **12** | 右髋 pitch | **22** | 左髋 pitch | **32** | 头 yaw |
| **13** | 右膝 | **23** | 左膝 | **33** | 头 roll |
| **14** | 右踝 | **24** | 左踝 | **34** | 嘴 |

**开保护**（跟改 ID 一起做，每颗都要）：出厂只开着「过热」，**过流、过压要自己开**。

页面上「单颗操作 → 写寄存器」：地址 **19 · 卸载条件**，字节 **1**，值写 **`13`**（= 过压 1 + 过热 4 + 过流 8），勾上「**解锁写（EEPROM 落盘）**」，点「写」。写完会自动回读核对，对不上会报错。

| 寄存器 | 名字 | 出厂 | 改成 |
|---|---|---|---|
| **19** | 卸载条件 | 只有过热（4） | **过热 + 过流 + 过压** → 写 `13` |
| 13 / 14 / 15 | 温度上限 / 最高·最低输入电压 | 出厂值 | **不动** |
| 波特率、运行模式 4、Return delay | — | 出厂值 | **不动** |

⚠️ **别去动 41 · 加速度** —— 那是 SRAM 里的运行参数，不是保护开关。

省事的办法：先按第 5 节跑一遍只读体检，它会把 15 颗的保护开关列出来、没开的标红，再回页面按缺的补。

改完**断电重启再扫一次**（第 5 节），EEPROM 参数要断电才是确定的。

## 4. 校准（一键校准）

⚠️ **什么时候别校**：**台架上的单颗裸舵机不要校准**。校准的定义是「把**此刻的物理位置**定义成 2048」——裸舵机没装到关节上，此刻的位置只是它随手停的地方，定成 2048 没有意义；而且飞特出厂 `偏移=0` 时 `2048` 本来就是舵机自己的机械中位，新舵机等于出厂就校好了。

**校准的正确时机**：把舵机装到关节上 → 舵盘对好齿 → 把关节摆到该关节的零位 → 这时才校。作用是补「舵盘齿对不齐」的那几度；要是齿正好对上，不校也能用。

台架上单颗只做两件事：**改 ID**（第 3 节）+ **开保护**。校准留到整机组装那一步，跟其他关节一起校。

跟 Windows 一模一样的两种基准，页面里「一键校准」区块：

```
1  把鸭子摆成基准的样子（推荐「官方折叠（头颈摆正）」，摆法看界面提示和调试记录）
2  基准下拉选「官方折叠（头颈摆正）」→ 页面自动把「校准哪些」填成 20-24,30-34,10-14，3D 叠加出该摆的样子
3  照 3D 摆好 → 点「一键校准」
4  确认框逐颗列「现在 → 写成、差几度」，看一遍再点确定
5  差 30° 以上的会再确认一次，看清楚是哪几颗、为什么
```

**Mac 上要注意的**：

- **台架上的单颗裸舵机，「一键校准」和「校准这一颗」都别点**（理由见本节开头）。真机校准用 **0x0B 位置校准指令**，不是「把当前位置当 2048」那种假校准
- **真机校准会顺带挪 `poses/` 里的姿态文件**（改了零点，里面存的读数要跟着换算），完成后 `git status` 会看到姿态被动过。**撤销**会把偏移和姿态一起还原，备份改名成 `calib/undone-…` 留档
- 扭矩是自动管理的：逐颗 解锁 → 读位置 → 关扭矩 → 0x0B → 读回 → 对上才改目标 → 扭矩复原 → 加锁。关扭矩只有几毫秒，关节不会被重力压下去
- **校完零点就是官方 2048**，别的代码不用加 offset

## 5. 验证 & 体检

**断电重启 → 再扫一次**，确认新 ID 都在：

```bash
cd tools/servo-web
.venv/bin/python servo_report.py --port /dev/cu.wchusbserial110
```

**只读，不写舵机任何寄存器。** 报告落在 `logs/体检-时间.md`（给人看）+ 同名 `.json`（0–86 全部原值）。

| 场景 | 命令 |
|---|---|
| 15 颗都接着 | `--port /dev/cu.usbmodem1101` |
| 总线上只接一颗 21 | `--port /dev/cu.usbmodem1101 --ids 21` |
| 不知道 ID（新舵机出厂 1） | `--port /dev/cu.usbmodem1101 --scan-all` |

判据按[调试记录第 5 步](../../调试记录.md#第-5-步--改参数)：过热、过流、过压三个保护都要开，没开标红。

跑之前**先关掉调试台**，串口只有一个。

## 6. 排错

| 现象 | 先查 |
|---|---|
| `ls /dev/cu.*` 里没有 USB 串口 | 驱动（第 1 节）；换根 USB 线 / 换个口；USB-C 转接头有的只有供电没有数据 |
| 页面里「全网扫描」扫不到任何东西 | 上电顺序（先 USB 后舵机）；S / G 接反；波特率必须 1 Mbps；临时插孔的 S 线最可疑 |
| 15 颗全不应答，总线 S–G 只有 2.1 V | 上电顺序反了，两边都断开重来（[踩坑记录 · 工具](../../踩坑记录.md#工具)） |
| 串口被占用、打不开 | 有别的程序占着：`lsof /dev/cu.usbmodem1101`，关掉它（调试台 / `servo_report.py` / FD / 串口助手） |
| 界面上「连接」点了没反应 | 顶栏「刷新」重新列串口；拔插 USB 后口号会变 |
| 写得进去、读回不对 | 页面「写寄存器」会自动回读核对；EEPROM 区要先勾「解锁写」，写完断电重启才算数 |

日志在 `tools/servo-web/logs/servo-web-日期.log`，原始收发、寄存器名、舵机应答都在里面，出问题把这个文件发出来就能查。

`--fake` 起一个不接舵机的，可以先在 Mac 上把改 ID、一键校准、撤销整个流程点一遍（**只改虚拟舵机，不碰真机、不碰 `calib/`**），熟了再上真机。
